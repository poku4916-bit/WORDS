Sites 的部署归档解压上限为 256 MiB；原始词典 JSON 约 325 MiB，首次发布因此被拒绝。当前生产构建在 Vite 输出后将全部 512 个词典分片保存为 `.json.gz`，约 57.82 MiB；manifest 标记压缩格式，浏览器按需解压后仍验证原始长度、SHA-256 和结构。所有 772,845 条词条保留；开发服务仍读取 `public/` 中的原始 JSON。构建预算检查会逐一解压校验生产分片，并检查整个 `dist` 小于归档上限。

线上解压使用浏览器的 [DecompressionStream gzip 标准](https://compression.spec.whatwg.org/)。不支持该 API 的旧浏览器会收到明确提示，建议更新浏览器；已保存词条仍可本地读取。

## 发布流程

1. 保留原项目 ID，更新现有网站。不得重复创建另一网站替代发布失败。
2. 类型检查、关键测试、生产构建与 `node scripts/check-budgets.mjs` 通过后，同步确切源码提交。
3. 打包该提交的生产输出和托管清单；个人浏览器数据、原始下载缓存、node_modules、开发组件展示页均不进入发布包。
4. 使用所有者私有发布操作；保留版本 ID、部署 ID 与源码提交 SHA。仅在发布状态成功且返回线上 URL 后确认上线。
5. 在正式地址检查词典 manifest 与分片、许可、查词收录、学习评分、刷新恢复、备份和移动布局。登录或浏览器权限限制导致不能验证的步骤需明确记录。

压缩版本的本地发布前验证已通过：39 项测试、类型检查、生产构建、512 个 gzip 分片的原始摘要校验；完整 `dist` 实测约 58.63 MiB。真实生产预览可通过浏览器解压读取 `light`，显示全部 48 条英文义项，控制台未捕获应用错误。最终线上状态仍以本次部署回执为准。

部署包及本次原始发布回执保存在被 Git 忽略的 `.deployment/`。源码凭据只在执行会话中使用，不写入配置、回执或 Git 历史。生产资源与词典仍由本项目的转换脚本复现。

## 词本迁移

localhost 开发服务、生产预览和正式网站属于不同来源，IndexedDB 互不共享。需要迁移时：

1. 在旧地址打开设置 → 备份恢复 → 导出 JSON。
2. 在正式地址登录并打开设置 → 备份恢复，选择 JSON。
3. 阅读新增和冲突预览，确认合并后检查词本、笔记和进度。

重复导入按事件 ID 去重。备份只合并个人数据，不恢复进行中的学习会话；换域名后完整离线启动仍未实现。

## 回退与后续更新

公开访问、自定义域名和云同步分别配置；本次私有发布不改变这些能力或权限。
